路径：侧边菜单 → 设置 → 模型设置 → 当前模型卡片（进入「模型」页）

填地址与密钥

支持官方接口和各类中转站。填好 Base URL 与 Key，点「测试」能拿到回复即可。

一个档案一个模型

同一条地址下可以建多个档案：便宜的快模型用来聊天，强的模型用来写代码，随时切换。

思考深度

支持推理的模型可以单独设深度；不支持也不会报错，会自动忽略这个设置。

02对话

这不是一个只能回字的对话框。文字、图片、文件、工具执行过程和图表可以同时出现在一条会话里； 它会自己拆步骤、调工具、看结果，再把结论放回你面前。

2.0 一屏之间的秩序

聊天页只做三件事：让你一眼看到"我在哪、它说了什么、我接下来能做什么"。 所有装饰都为这三件事让路 —— 没有多余的栏、没有抢注意力的边框、没有突然跳出来的面板。

留白

顶栏是"浮"的，不是"压"的

没有整条背板、没有发丝线，只有返回与更多两枚圆钮浮在内容上。消息从它们身后穿过去，屏幕从上到下是一整块连续的纸面。

层级

一眼分得清谁在说

你的话靠右、气泡收紧；它的回答靠左、占据整行阅读宽度。工具过程收成一行摘要，正文永远是视觉重心。

动效

形变，而不是切换

输入框收起时是同一个玻璃面在缩成圆：圆角、宽度、透明度连续变化；展开时内容不会"先扁一下再弹开"。

材质

只有一层玻璃

收起态的圆、模型胶囊、工具圆共用同一层玻璃与描边。并排放在一起，看不出"这个是组件、那个是画的"。

2.0.1 一屏的排布

区域里面有什么为什么这样排
顶部返回、会话名、更多只有两枚圆钮，没有背景栏；会话名只占一行，不参与抢视线
消息流用户气泡、AI 正文、工具摘要你靠右、它靠左；正文占满阅读宽度，工具过程默认折叠
输入区玻璃框、附件、模型胶囊、发送一整块玻璃，不切成好几个小控件；模型胶囊就是当前状态
浮层引用条、模型选择、工具详情用到才出现，出现时也只占一层，不改变页面结构

2.0.2 把输入框收起来

读长回答时，输入框是最大的一块"不属于内容"的东西。 它可以在一个手势里缩成一枚 46 像素的圆 —— 不消失、不换位置，只是收起身形。

能力说明

各自模型一个成员绑定一个模型档案，创作和审校可以来自两家

2.4 标记、引用与重点

标记和引用都锚在原文上：流式重绘、重新生成之后也不会跑位。

功能怎么用细节
划重点（手动）选中文字 → 选颜色黄 / 绿 / 蓝 / 粉四色；按「原文 + 第几次出现」定位，同样的字不会一起被标；重开应用仍在原位
取消 / 换色同一处再选一次再点可换色或取消，不会留下两块叠在一起的高亮
AI 也能标记它调用 mark 工具整理完长资料，它会把最该看的三行标出来；也可以标你说过的话
AI 标记的边界逐字照抄原文不能改写、不能只给关键词；同词多处用「第几次出现」；一次 1–3 处，满篇高亮等于没标
找不到时如实说找不到不硬标一段相近的 —— 标错比不标更糟
引用回复长按 → 引用并回复引用条挂在输入框上方可随时取消；发出后原文处留虚线锚点
重新生成长按某条 → 重新生成拿它当时看到的上下文重答一次；换模型后再重新生成，等于让另一个模型重做这一题
修改 / 复制长按自己的话 → 修改改完重发，后续基于新内容；复制拿到的是 Markdown 原文
标记存在消息数据里，不写进模型上下文 —— 它是"给你看的"，不是给模型看的。 所以标了也不会多花 token，重新打开会话仍在原位。

最多等 6 分钟；超时会明确告诉你"可能还在生成，过一会儿再查"，而不是假装失败。

和生图同构

只填模型名，地址与密钥沿用当前档案；对话模型能不能画图与此无关。

11.5 描述改进

你负责说人话，它负责把话补成能执行的任务；改写版可核对，不满意可关。

路径：设置 → 模型设置 → 描述改进（输入框的模型选择器里也能开关）

项说明
开关发消息前先把你的原话改写成更清楚的任务描述，再把改写版交给模型
低 · 最小改动只在指代不清、动作含糊时动手，句子结构和用词保持原样
中 · 默认补全指代、说明意图、去掉口语噪声，仍然保持一句话
高 · 写成任务描述允许重写成"目标 / 约束 / 产出"，缺的信息留成待确认项
改进用模型留空 = 用当前对话模型；建议填一个快模型，省时间也省钱
自定义要求原样追加给改写器，优先级最高；例如"把所有代词换成具体名字"
原话永远完整显示在消息里，改写版折在它下面 —— 发出去之前能核对。 代价是每次多一次往返（一两秒），所以默认关。

12联网、识图与知识库

会查、会看，还会读你自己的资料。搜索多通道自动降级；识图优先走多模态、 失败才 OCR 并如实说明；你的工具文件夹与工作空间，就是它随取随用的知识库。

12.1 联网搜索

一次搜索，三条通道兜底 —— 不把"搜不到"原样甩给你。

路径：设置 → 联网设置

通道说明
自动Tavily → Bing 直连 → 内置浏览器，依次尝试；前一条失败自动换下一条
只用 Tavily需要 Key；结果质量通常最好，速度快
只用内置浏览器不依赖任何 Key，通用但慢，适合被墙/需要 JS 的页面
搜索引擎浏览器抓取用 bing / duckduckgo / baidu / google；首页也跟随这个偏好
结果条数每次搜索返回几条；太多会挤占上下文
搜索失败时不要反复重试同样的关键词：结果里会写清哪条通道为什么失败， 直接把这个原因告诉用户，让他决定（比如是不是要填 Key）。

12.2 识图

先让模型真的看懂画面；模型不行才退回文字识别，而且如实告诉你。

路径：设置 → 联网设置 → 视觉接口地址 / Key / 模型（三项都可留空）

情况行为
当前模型勾了「支持图像理解」直接把图交给它看，不额外配置
当前模型不支持图像用同一套地址和密钥试一次默认视觉模型（deepseek-flash）
单独配了视觉模型优先用它；地址/密钥/模型名可以只填一两项，缺的复用主档案
全部失败降级为本地 OCR，第一句就说明"这只是 OCR、没有画面理解"，并附失败原因

先压图再发

长边缩放、只缩不放；能压进预算就保留原分辨率。截图上的小字因此更清楚。

格式按文件头认

不看扩展名。改名过的图片也不会因为 mime 发错被服务端 400。

接口地址容错

粘完整 …/chat/completions 不会重复拼接；只填主机名时会补 /mcp（MCP）。

12.3 知识库：把资料和做法放进「工具」

把做法和资料放成文件夹，模型需要时才读 —— 不是一次性塞进上下文。

路径：设置 → 关于 → 能力扩展 → 工具

一个工具就是一个文件夹：tool.md 写"这类事怎么做"，旁边可以放脚本、模板、参考文件。 模型觉得相关时才去读 —— 它既是"技能"，也是一份可检索的知识库。

能放什么例子
做法说明「合并 PDF：先按文件名排序，再调用 merge.py，最后检查页数」
脚本 / 模板merge.py、report.md、prompt.txt
领域资料接口约定、字段解释、公司术语表、常用命令清单
与规则的区别规则永远生效（约束）；工具按需取用（做法与资料）
工作空间里的文件同样是知识库的一部分：模型能直接读写它们， 不需要你把内容复制进对话。长期有效的事实放记忆，操作经验放自学习， 成套做法放工具 —— 三者别混。

14字体、字号与横屏工作流

看得清，也放得下。字体文件运行时加载，字号 85%–140% 可调，横屏还有独立倍率； 横过来不是拉伸，而是左聊天、右工具表的专业工作流。

14.1 字体

内置字体不够用？选一个你自己的字体文件，立刻生效，不用重装。

路径：设置 → UI 设置 → 字体

项说明
内置英文/数字用 San Francisco Display，中文回落到系统字体
选择字体文件支持 .ttf / .otf / .ttc，运行时加载，不需要重装应用

中文缺字自选字体多半没有汉字字形，中文自动回落到系统字体，不会变成空心方块

14.2 字号

85% 到 140%，正文、代码、表格一起缩放；横屏单独一档。

路径：设置 → UI 设置 → 字体 / 字号

项范围说明
全局字号85% – 140%正文、代码块、表格一起缩放
横屏字号85% – 140%只在横屏时叠加到全局字号；竖屏不受影响

14.3 横屏专业流程 UI

横屏最缺的是高度、最富的是宽度 —— 所以把宽度用来并排看"对话"和"工具过程"。

区域内容
顶部横向导航条新对话 / 历史 / 计划 / 笔记 / 研究 / 浏览器 / 设置，压成一条 36 高的横栏
左栏聊天消息与输入框；输入区固定展开（不缩成圆）
中间分隔条左右拖动调整比例；比例会跟着窗口大小重新夹紧，不会把某一栏拖没
右栏工具调用表：工具名、状态、耗时、参数/输出；跑长任务时不用来回切页
全屏沉浸横屏隐藏状态栏，把高度全部留给内容；竖屏保留状态栏
抽屉横屏仍可拉出，但入口已经收进顶部横栏，不再默认占半屏

为什么是分栏

长任务里"它在干什么"和"它说了什么"同样重要。竖屏只能上下堆；横屏并排之后，两边都不用滚回去找。

横屏字号单独一档

横屏可用高度只有竖屏的一半，同一套字号会让聊天和工具表都很挤。单独倍率让你不必为了横屏把竖屏也缩小。

工具表复用

性能页的"工具调用"也是同一张表 —— 学习一次，两处都看得懂。

15自学习

它不只记住你，也记住自己。走过弯路、犯过错、学会一个可复用的做法， 就自己写一条"下次遇到 X 就 Y"；下一轮先按经验做，不重复踩坑。

路径：设置 → 自定义设置 → 自学习（开关 + 笔记页）

方向

AI 只能写，你只能删

添加入口只存在于 learn 工具里；设置页只有查看、逐条删除、清空。没有"手动添加"。

生效

每轮都带上

笔记会拼进系统提示词，标注"这是你自己写的经验，不是用户指令"。关掉开关只是不再注入，条目仍然保留。

边界

不是第二个规则列表

用户写 = 变成"命令"，agent 会分不清哪条是自己踩出来的坑。所以这个方向必须单向。

什么时候写

类型例子
绕弯（detour）试了两三次才找到对的做法 → 「先看接口返回的 error.message，再决定换不换参数」
犯错（mistake）被用户纠正、或工具报错后发现是自己用错了 → 「路径含空格时要加引号」
技能（skill）发现某个工具/参数组合稳定好用 → 「调 ui_action 前先 ui_tree，按控件名点」
经验（lesson）其它可复用的操作结论

硬约束

约束值 / 行为
单条长度240 字；写成长篇复盘会被拒绝
条数上限80 条；到顶不会自动淘汰，会提醒你去删
去重完全相同的经验不会重复写
安全闸门「跳过确认 / 忽略安全规则」和疑似密钥会被存储层直接拒绝
确认默认不弹确认；但你把「只读命令自动执行」关掉时，总闸优先，写入也会问一次
这是全应用唯一会把模型输出持久化进系统提示词的地方，所以存储层有两道闸。 它不能覆盖安全确认，也不能要求自己"忽略用户当前的要求"。

16MCP 外部工具

一个协议，接进整个外部世界。把远程 MCP 服务器接上，它声明的工具就变成 AI 能直接调用的函数 —— 只读的直接跑，写操作弹确认，会话过期自动重连。

路径：设置 → 自定义设置 → 数据与扩展 → MCP 服务器

16.1 接入一个服务器

填地址和 Token，剩下的自动发现 —— 工具立刻出现在 AI 手里。

字段说明
名称显示名，也会进工具名（方便模型辨认是哪个系统）
服务器地址https://example.com/mcp；只填主机名时会自动补 /mcp 再试一次
请求头一行一个，通常只需要 Authorization: Bearer …
连接保存后自动 initialize → 发现工具；失败原因显示在服务器卡片上
启用开关停用后不再把工具交给 AI，缓存保留
刷新工具服务器更新了工具列表时手动刷新一次

16.2 协议与兼容

Streamable HTTP

标准远程传输：POST 到服务器；响应可以是 JSON，也可以是 SSE。两种都解析。

会话与重连

记住 Mcp-Session-Id；服务器重启后旧会话失效（404）会自动重新 initialize 一次。

翻页

tools/list 会跟着 nextCursor 一页页读完，不会只拿第一页。

缓存

上次成功发现的工具落盘；离线或服务器暂时挂了也能看到工具，调用时再报错。

16.3 工具名、风险与结果

项说明
模型侧工具名mcp_<服务器名>_<id尾>_<工具名>，保证合法、唯一、≤ 64 字符
只读工具服务器声明 readOnlyHint 时直接执行
写操作走现有确认框；destructiveHint 会额外标明"可能造成破坏"
返回内容文本直接展开；图片存成文件并给路径（可再用 read_image 看）；资源/结构化结果也保留
schema 清洗只保留各家都认的 JSON Schema 字段；$ref / oneOf 等会被丢掉，避免整个请求 400
系统提示接入的服务器与工具标题会列进提示词，降低"模型没想到用"的概率

16.4 排查

症状先查什么
401 / 403Headers 里的 Token 是否正确、是否过期
404地址是否少了 /mcp；会话过期时刷新一次即可
连上但没有工具点「刷新工具」看错误；服务器可能要求 Accept: text/event-stream（客户端已自动带）
工具不出现服务器开关是否启用；当前模型档案的工具白名单是否把它裁掉了
调用超时单次 3 分钟；长任务建议在服务器侧改成异步任务 + 轮询

17内容尺度

同一套模型，不同的回答尺度。成人内容、政治议题、题目查询三档可调； 它约束的是表达方式 —— 边界写清楚，不给你假的安全感。

路径：设置 → 关于 → 内容尺度 → TeenSpace

项目管什么严格档
成人 / R 级内容包含性、暴力、血腥描写的提问与创作拒绝直接描写，只给概括或建议换个方向
政治议题时政评论、立场分析、敏感历史事件只陈述事实、不给立场判断，也不做预测
题目查询作业题、考试题、竞赛题不直接给最终答案，讲思路、指出卡在哪一步
这不是内容过滤器。本地没有语义理解能力，判断不了"什么算政治议题"。 这三档写进系统提示词，约束模型的表达；绕过它的方式也很直接 —— 换个话题、或换个模型。把边界说清楚，比给一个假的安全感好。

三档怎么选

档位适合
宽松成年用户、自己知道要什么；模型按正常尺度回答
标准默认；敏感话题给概括与事实，不展开细节
严格共用设备、青少年使用；三类内容都收紧

SPEC主题包规范

主题包不是"换张皮"，是把聊天界面的整页控制权交出去。数据结构、双向接口、 消息格式、沙箱边界和性能红线，下面逐条写死 —— 照这份写，行为就是确定的。

S.1 一个主题包是什么

字段类型说明
idstring应用生成；内置包固定为 builtin
namestring列表里显示的名字
seednumber主题色，ARGB 整数，如 0xFF1F4B3F
htmlstring整页 HTML（含 CSS / JS），上限 512 KB
builtinboolean内置示例：不可删、不可改

存储格式

{
  "activeId": "p1730000000000000",   // 空串 = 用应用默认界面
  "packs": [
    { "id": "builtin", "name": "内置示例", "seed": -11090049,
      "html": "<!DOCTYPE html>…", "builtin": true }
  ]
}

一份 JSON 就是完整备份：导出发给别人、对方导入即可用。超过 512 KB 会被拒绝保存而不是截断 —— 截断后的 HTML 是"少了半截脚本"的坏包，比拒绝更难查。

S.2 生命周期

宿主 写文件 → 用 file:// 加载页面
  → onLoadStop
      → onTheme(colors)          一次
      → onState(state)           一次
      → onMentions({…})          一次
      → onMessages(list, busy)   一次
  → 之后的变化按需推送
用 file:// 而不是内联注入，是为了让页面能直接引用本地图片 （<img src="file:///…">）。内联页面的源是 about:blank， 本地子资源会被当跨源拒绝。

S.3 调用守卫（很重要）

宿主每次调用前先检查方法是不是函数：

(window.App && typeof window.App.onMessages === "function")
  && window.App.onMessages(list, busy);

所以你可以只实现其中几个 —— 没实现的不会报错，也不会弹红字。 但必须写成函数值：window.App.onState = {…} 会被跳过。

handler参数行为

S.5 宿主 → 页面（6 个回调）

onMessages(list, busy)

全量推送当前会话；busy 表示这一轮是否还在生成。

每次调用都代表「这就是全部消息」。不要往列表里追加 —— 流式时每秒推数次，追加会得到 N 条重复。

onTheme(colors)

key类型含义
primary'#RRGGBB'强调色
onPrimary'#RRGGBB'压在强调色上的文字
surface'#RRGGBB'卡片 / 控件填充
page'#RRGGBB'页面底色
text'#RRGGBB'主文字
muted'#RRGGBB'次要文字
bubble'#RRGGBB'用户气泡底色
darkboolean是否深色（真布尔，不是字符串）
fontScalenumber全局字号缩放

调用时机：页面加载完成、系统深浅色切换、字号变化。

onState(state)

key类型含义
busyboolean这一轮是否在生成
modelstring当前模型的显示名
canStopboolean是否可停止
pendingAttachmentsnumber待发附件条数

onPatch(index, msg, busy)

流式输出时只有最后一条在变，宿主只推这一条。实现它，出字时就不用重绘整个列表 —— 这是「流式不卡」最有效的做法。不实现也能用（退回全量）。

onMentions({tools, plugins})

可被 @ 的工具与插件清单（{id, title, note}），用来画自己的 @ 选择器。

onSendResult(ok, errorText)

当前版本预留，宿主尚未调用；实现无副作用，但别依赖它做唯一反馈。

S.6 消息对象

{
  role: 'user' | 'assistant',
  content: string,        // Markdown 原文，宿主不做 HTML 渲染
  reasoning: string,      // 思考过程
  reasoningMs: number,    // 思考耗时
  pending: boolean,       // 该条仍在流式生成
  error: string | null,
  marks: [{ text, occurrence, color, kind }],
  quote: { text, color } | null,
  tools: [{
    name, summary,
    status: 'awaitingConfirm' | 'running' | 'success' | 'failed' | 'rejected',
    args: string,         // 参数原始 JSON 字符串
    output: string,
    error: boolean
  }]
}
content 是 Markdown 源文。不要直接 innerHTML = content —— 那等于把模型输出当 HTML 执行。要么自己解析，要么 textContent 原样显示。

标记颜色

color含义
yellow默认荧光笔
green / blue / pink其它荧光笔色
quote引用锚点（虚线），系统保留

S.7 推送节流与截断

规则值为什么
指纹比对条数 + 最后一条内容/思考/pending/error + busy没变就不推
按消息缓存只有变化的那条重新编码长会话不必整段重算
增量通道onPatch 约 60ms跟得上出字速度
全量间隔<16KB→120ms；16–48KB→180ms；>48KB→260ms载荷大时别排队堆积
reasoning 上限4000 字跨桥体积
tools args / output各 1200 字命令输出可能上百 KB

推论：收到的是近似连续而非逐字更新；也不要假设 args / output 完整（超长会标注「已截断」）。

S.8 本地图片与文件

做法说明
<img src="file:///…">页面从 file:// 加载，本地图片可直接显示
App.image(path)返回 data: URI；失败返回 ! 开头的原因
App.images(text)解析正文里的 Markdown 图片，返回 [{alt, src, remote, data}]
App.open(path)用系统查看器打开文件

可读目录：应用私有目录、外部私有目录（含附件）、相册与下载。单张图上限 6 MB，一条消息最多 24 张。

// 一定要在页面端缓存 data URI
const cache = new Map();
async function pictureFor(im) {
  if (im.remote) return im.src;
  if (cache.has(im.src)) return cache.get(im.src);
  const d = await window.App.image(im.src);
  if (d.startsWith('data:')) cache.set(im.src, d);
  return d;
}

S.9 沙箱边界

设置值结果
javaScriptEnabledtrue页面可以跑脚本（这是功能定义）
allowFileAccesstrue页面能引用本地图片与文件

边界说清楚：页面既能读本机文件、也能联网，请只放自己信任的 HTML。 需要外部信息更推荐走 App.send() 让 agent 去取 —— 那条路有确认、有记录。

S.10 性能硬要求

禁止 / 要求原因
❌ backdrop-filter: blur()Android WebView 上每帧重模糊整个可视区，滚动直接掉帧
❌ 每次推送 innerHTML = ''每秒数次 × 几十条 = 每秒重建数百节点，滚动位置也被重置
✅ 条数不变只更新最后一条消息只会追加或整条替换，这个判断安全
✅ 长列表用固定容器 + overflow-y:auto避免整页撑高导致布局抖动
✅ 大图懒加载 / 内联 SVG解码大图会卡主线程

S.12 排查

症状先查什么
一片白屏宿主会弹一条错误提示（加载失败 / JS 报错 / 注入失败），先看它

GUIDE操作指南（逐步）

从第一次打开到每一个高级开关，按编号一步步来。不熟的地方不用猜，照着点就行； 每一步都写清"在哪、点什么、看到什么、怎么改回来"。

G.1 第一次打开应用

  1. 打开应用 → 左上角圆形按钮打开侧边菜单
  2. 点「设置」→ 找到「模型设置」
  3. 点「新建档案」，依次填：显示名、Base URL、API Key、模型名
  4. 点「测试」—— 能收到一句回复就说明通了
  5. 返回聊天页，输入框上方会显示这个档案的显示名
填错时不要反复重发消息：先在设置里点「测试」，那一步失败会直接告诉你 是地址不对、密钥不对，还是模型名不存在。

G.2 发一条消息

  1. 在输入框里描述任务，可以只说目标，不用管步骤
  2. 需要附件时点左边的 ＋：选图 / 选文件，缩略图会挂在输入框上方
  3. 点右侧圆形按钮发送；生成中它会变成停止
  4. 想中途叫停：点停止，已生成的内容会保留

G.3 换模型

  1. 点输入框上方的模型胶囊（显示当前档案名）
  2. 在列表里选另一个档案 → 立即生效，历史继续沿用
  3. 同一次弹层里还能调思考深度（仅对支持推理的模型有意义）

也可以走：聊天右上角圆按钮 → 选择模型，两个入口等价。

G.4 标记与引用

  1. 长按消息里的文字 → 选中一段 → 选择颜色，即完成划重点
  2. 想取消：同样的位置再长按 → 选「取消标记」
  3. 想接着某句说：长按 → 「引用并回复」→ 引用条出现在输入框上方
  4. 发出去后，原文那里会留一道虚线锚点，回头能看出"这句话被接过"

G.5 建一个群聊

  1. 侧边菜单 → 底栏「群聊」
  2. 依次添加成员：给每个成员起名、写人设、选模型（可以只填"跟随当前模型"）
  3. 成员清单里的顺序就是发言顺序，拖动即可调整
  4. 在输入框用 @ 点名某个成员，只有他回答；不 @ 则全部按顺序回答
  5. 想插话：直接输入并发送；想打断：点停止

G.6 存一套做法（自定义工具 / 知识库）

  1. 设置 → 关于 → 能力扩展 → 工具 → 右上角「新建工具」
  2. 填名字（如 合并PDF），进入详情页
  3. 编辑 tool.md：写清"什么时候用、怎么做、注意什么"
  4. 需要脚本就新建文件（如 merge.py），引用路径写相对名
  5. 回到聊天里说「用合并PDF处理这个目录」，模型会读那份说明

G.7 写一条规则

  1. 设置 → 自定义规则 → 新建
  2. 写一句可判定的话，例如「回答先给结论，再给理由」
  3. 保存后立刻生效，之后每一轮对话都受它约束
规则和"记忆"的区别：规则是硬性约束（永远照做），记忆是关于你的事实（会被引用）。 不要把所有偏好都写成规则 —— 太多规则会互相打架。

G.8 让它记事

  1. 直接说「记一下：下周要去上海出差三天」
  2. 它会存进笔记（或计划，看内容性质）；长期事实才进记忆
  3. 之后问「我下周有什么安排」，它会翻出来回答
  4. 想改：笔记页可编辑；记忆只能手动添加 / 逐条删除 / 整体关闭

G.9 开一个常驻聊天（autopilot）

  1. 在聊天右上角打开 Autopilot 文件夹；也可以直接说「每天八点把天气发给我」，让它用 autopilot 的 resident 动作写脚本
  2. 文件夹里点「新建」，填文件名（如 check.sh）与内容，保存
  3. 选间隔：10s / 30s / 60s / 5m / 30m，或「自定义」输入 45、5m、2h
  4. 填「AI 反馈模型」（这条聊天专用的模型名）并选反馈强度；留空会跳过 AI
  5. 打开「常驻运行」；想立刻验证就点脚本行的 ▶
  6. 脚本输出 false / 空 = 不叫 AI；输出 true + 内容 = 卡片进当前聊天，由聊天 AI 处理
  7. 侧边菜单的历史列表里，这条会话标题左边会出现循环箭头图标

G.10 写一个能用的常驻脚本

原则只有一条：没事发生就不要有输出。

#!/bin/sh
# 有情况才 echo，没情况直接 exit 0
value=$(curl -s "https://example.com/api/state" | jq -r '.value')
[ "$value" = "ok" ] && exit 0        # 正常 → 静默
echo "状态异常：$value"               # 异常 → 输出，模型会被叫醒
输出情况会发生什么
没有输出 / 只有空格继续下一轮，模型完全不被调用
和上一轮一样同上（这轮当作没变化）
和上一轮不同内容交给模型，结论回到这个会话；应用在后台时另发通知

G.12 加一把锁

G.16 打开输入改进

  1. 输入框旁的模型选择器里找到「描述改进」开关，先打开
  2. 想细调：设置 → 模型设置 → 描述改进
  3. 先选档位（低 / 中 / 高）；不确定就用「中」
  4. 「改进用模型」建议填一个快模型，省一次长等待
  5. 发一句省略的说法试试；原话在上、改写版折在下面，核对后再发

G.17 让 AI 标重点 / 引用

  1. 在长回答后直接说「把最该看的三行标出来」
  2. 它调用 mark 工具，只标逐字出现过的原文；找不到会如实说
  3. 想让它标你说过的话：说「标一下我上面说的预算数字」
  4. 自己标：选中文字 → 选颜色；再点同一处可换色或取消
  5. 引用：长按 → 「引用并回复」；发出后原文处留虚线锚点

G.18 接一个 MCP 服务器

  1. 设置 → 自定义设置 → 数据与扩展 → MCP 服务器
  2. 点右上角「+」：填名称、地址（如 https://example.com/mcp）
  3. 需要鉴权就加一行 Authorization: Bearer …
  4. 保存后自动连接并发现工具；失败原因直接显示在卡片上
  5. 进详情页可以看工具清单、刷新、启用 / 停用
  6. 回到聊天，直接说需求；工具名以 mcp_ 开头，写操作会弹确认

G.19 看它学到了什么

  1. 设置 → 自定义设置 → 自学习 → 自学习笔记
  2. 列表里每条都带分类（犯错 / 绕弯 / 技能 / 经验）和时间
  3. 只能逐条删除或清空；没有添加入口
  4. 不想让它带上这些：关掉「启用自学习」；笔记仍保留

G.20 横屏工作流

  1. 把手机横过来：顶部出现横向导航条（新对话 / 历史 / 计划 / 笔记 / 研究 / 浏览器 / 设置）
  2. 左栏聊天，右栏工具调用表；拖动中间分隔条调整比例
  3. 长任务时右栏直接看每一步的参数与输出，不用来回切页
  4. 觉得字太挤：设置 → UI 设置 → 横屏字号，单独调小一档

G.21 换字体 / 字号

  1. 设置 → UI 设置 → 字体 → 「选择字体文件」
  2. 选一个 .ttf / .otf / .ttc；立即生效，不用重启
  3. 中文缺字会自动回落到系统字体；代码块仍然是等宽字体
  4. 字号滑杆：85% – 140%；横屏另有独立倍率
  5. 想回去：点「恢复默认」

G.22 生图 / 视频

  1. 设置 → 模型设置 → 填「生图模型名」（如 gpt-image-2）
  2. 需要视频再填「视频模型名」；两者都用当前档案的地址与 Key
  3. 回到聊天直接说「画一张…」或「生成一段…视频」
  4. 改图：把源图作为附件发过去，说「把背景换成…」；它会走图生图
  5. 结果是文件卡片；长视频异步生成，超时会提示过一会儿再查

G.23 学业 / 研究流程

  1. 侧边菜单底栏 → 研究：输入题目，等它拆题、检索、交叉验证
  2. 报告出来后点「存成笔记」；按课程或项目归档
  3. 读论文：把 PDF / 网页发进对话，让它分段读、给摘要与局限
  4. 要推导或公式：直接让它写 LaTeX，消息里会渲染成公式
  5. 复习：把要点让它画成思维导图，或在计划里建复习待办
