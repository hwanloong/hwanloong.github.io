01快速开始

三步就能让它干活。

第一步 · 配一个模型

路径：侧边菜单 → 设置 → 模型设置

填地址与密钥

支持官方接口和各类中转站。填好 Base URL 与 Key，点「测试」能拿到回复即可。

一个档案一个模型

同一条地址下可以建多个档案：便宜的快模型用来聊天，强的模型用来写代码，随时切换。

思考深度

支持推理的模型可以单独设深度；不支持也不会报错，会自动忽略这个设置。

第二步 · 打开需要的权限

路径：设置 → 能力扩展

权限给什么能力不给会怎样
无障碍读屏幕控件、点击、滑动、输入只能聊天，不能操作界面
通知读取把系统通知交给自动化当触发源自动化只能按时间跑
屏幕录制看到画面内容（截图理解）看不了屏幕上的图形信息
电池优化白名单后台长任务不被系统掐断息屏后任务可能被暂停

第三步 · 说第一句话

在输入框里直接描述任务即可，不需要学语法。

你：看看我手机的存储还剩多少，哪个目录最占地方

05内置 Linux 环境

开箱即用的 Alpine，不依赖 Termux，也不需要 root。

零配置

首次使用自动解压环境；之后模型可以直接 apk add、pip install，装完就能用。

双向可见

应用生成的文件 Linux 能直接跑；Linux 生成的文件应用能直接点开 —— 不用来回复制。

能上网

06常驻自动化

让一条聊天变成「一直盯着」的助手：定时跑脚本，有事才叫你。

怎么开

在输入框里提到 autopilot（手打或从 @ 面板选）→ 这条聊天立刻变成常驻聊天

出现的东西位置
自动化图标侧边菜单历史列表里，那一条会话标题左侧（运行中为强调色）
Autopilot 文件聊天右上角「更多」菜单里，进去就是脚本与间隔

脚本空间

自动化 · 每 60 秒
循环箭头　常驻运行开
计时器　执行间隔60s · 5m · 自定义
脚本
check_mail.sh▶　删除
watch_stock.py▶　删除
最近一次输出
未读 3 封，最新：季度报表

Autopilot 文件页：开关、每个脚本各自的间隔、脚本列表与最近输出都在同一屏。

隔离

每条会话一个目录

.sh / .py 各放各的。抓邮件的脚本不会跑到盯盘任务里拿错参数。

每个脚本自己的间隔

抓邮件 1 分钟、盯盘 5 秒、日报 1 天一次，各设各的，互不迁就。

随时手动跑一次

脚本行右边的 ▶ 就是"现在跑一轮"，方便调试，不影响定时。

判断逻辑：什么时候叫模型

脚本输出行为
空 / 只有空白这一轮没事发生，继续循环，不打扰模型
与上一轮完全相同同上（很多脚本会无脑打印"没有新邮件"）
有变化叫醒模型处理，把结论放回会话；后台时另发通知

一份能直接用的脚本

#!/bin/sh
# 每 60 秒跑一次：有未读才输出，没有就什么都不打印
count=$(curl -s "https://mail.example.com/api/unread" | jq -r '.count')
[ "$count" -gt 0 ] || exit 0            # 没有新邮件 → 静默
subject=$(curl -s "https://mail.example.com/api/latest" | jq -r '.subject')
echo "未读 ${count} 封，最新：${subject}"

在后台也不错过

前台

内容进当前会话 + 历史列表标红点，不额外发通知（你正在看）。

后台

上面两条之外，再发一条系统通知 —— 划得掉、点开回到对应会话。

保活

长任务跑起来有常驻通知；配合电池白名单，息屏也能继续。

07可替换的界面

聊天界面可以用自己写的 HTML 重做 —— 也可以让 AI 帮你写。

路径：设置 → UI 设置 → 外观 → 主题包（HTML 界面）

主题包是什么

名字 + 主题色 + 一整页 HTML。列表里可以并存多个，随时切换；选「应用默认界面」就回到原生。

能拿到什么

消息全文（含思考与工具调用）、当前模型、附件条数、主题色、明暗、字号。

能做什么

发消息、停止、换模型、选文件/图片、读剪贴板、打开本地文件、显示本地图片。

最小可用的页面

<script>
// 应用推数据给你
window.App.onMessages = (list, busy) => {
  // list: [{role, content, reasoning, pending, error, tools}]
};
window.App.onTheme = (c) => {
  document.documentElement.style.setProperty('--page', c.page);
  document.documentElement.style.setProperty('--text', c.text);
};
window.App.onState = (s) => { /* s.model / s.busy / s.pendingAttachments */ };

// 你发消息给应用

  window.flutter_inappwebview.callHandler('send', text);
}
</script>
让 AI 写最快：说一句「把聊天界面做成深色极简，带思考折叠」，它会生成一个主题包， 你切过去看效果、不满意继续让它改。写坏了切回默认界面即可，不影响任何数据。

08密码与安全

锁的粒度由你定 —— 可以只锁笔记，也可以锁整个应用。

路径：设置 → 密码与安全

保护范围什么时候要验证
打开应用每次冷启动
设置进入设置页（内含模型与密钥）
笔记进入笔记页
计划进入计划页
记忆进入记忆管理
规则进入规则列表
工具进入工具页
敏感权限进入权限相关入口

两种解锁方式

密码，或者系统自带指纹 / 面部 / PIN。生物识别由系统界面完成，应用只拿到通过与否。

验证过的状态只在内存

进程结束就清空 —— 这就是"下次打开还要验证"的实现，不需要额外设置。

模型也会来问你

执行危险操作前它会主动弹一次验证。拒绝 → 立即停止，不会绕别的路继续。

它：准备删除 Download 下 12 个三个月前的安装包，共 1.8 GB。
     （弹出验证窗口）
你：拒绝
它：已停止，没有删除任何文件。

SPEC主题包规范

主题包把聊天界面整页交给一份 HTML。下面把数据结构、双向接口、消息格式、 沙箱边界与性能要求逐条写清 —— 照这份写，行为就是确定的。

S.1 一个主题包是什么

字段类型说明
idstring应用生成；内置包固定为 builtin
namestring列表里显示的名字
seednumber主题色，ARGB 整数，如 0xFF1F4B3F
htmlstring整页 HTML（含 CSS / JS），上限 512 KB
builtinboolean内置示例：不可删、不可改

存储格式

{
  "activeId": "p1730000000000000",   // 空串 = 用应用默认界面
  "packs": [
    { "id": "builtin", "name": "内置示例", "seed": -11090049,
      "html": "<!DOCTYPE html>…", "builtin": true }
  ]
}

一份 JSON 就是完整备份：导出发给别人、对方导入即可用。超过 512 KB 会被拒绝保存而不是截断 —— 截断后的 HTML 是"少了半截脚本"的坏包，比拒绝更难查。

S.2 生命周期

宿主 写文件 → 用 file:// 加载页面
  → onLoadStop
      → onTheme(colors)          一次
      → onState(state)           一次
      → onMentions({…})          一次
      → onMessages(list, busy)   一次
  → 之后的变化按需推送
用 file:// 而不是内联注入，是为了让页面能直接引用本地图片 （<img src="file:///…">）。内联页面的源是 about:blank， 本地子资源会被当跨源拒绝。

S.3 调用守卫（很重要）

宿主每次调用前先检查方法是不是函数：

(window.App && typeof window.App.onMessages === "function")
  && window.App.onMessages(list, busy);

所以你可以只实现其中几个 —— 没实现的不会报错，也不会弹红字。 但必须写成函数值：window.App.onState = {…} 会被跳过。

S.4 页面 → 宿主（11 个通道）

handler参数行为
sendtext发一条消息，走与用户点发送完全相同的流程
stop—停止生成（真的取消请求）
pickModel—打开原生模型选择器，选完经 onState.model 回传
pickFile—系统文件选择器，选中后进入待发附件
pickImage—系统图片选择器
paste—返回剪贴板文本（可空串）
imagepath返回该图片的 data: URI；失败返回 ! 开头的原因
imagestext解析 Markdown 里的图片，返回 JSON 字符串
openpath用系统查看器打开文件；空串 = 成功
mark{index, text, occurrence?, color?}给第 index 条里的那段文字打标记
quote{index, text}引用那一段，下次发送会带上
// 调用方式
window.flutter_inappwebview.callHandler('send', '你好');
const text = await window.flutter_inappwebview.callHandler('paste');

S.5 宿主 → 页面（6 个回调）

onMessages(list, busy)

全量推送当前会话；busy 表示这一轮是否还在生成。

每次调用都代表「这就是全部消息」。不要往列表里追加 —— 流式时每秒推数次，追加会得到 N 条重复。

onTheme(colors)

key类型含义
primary'#RRGGBB'强调色
onPrimary'#RRGGBB'压在强调色上的文字
surface'#RRGGBB'卡片 / 控件填充
page'#RRGGBB'页面底色
text'#RRGGBB'主文字
muted'#RRGGBB'次要文字
bubble'#RRGGBB'用户气泡底色
darkboolean是否深色（真布尔，不是字符串）
fontScalenumber全局字号缩放

调用时机：页面加载完成、系统深浅色切换、字号变化。

onState(state)

key类型含义
busyboolean这一轮是否在生成
modelstring当前模型的显示名
canStopboolean是否可停止
pendingAttachmentsnumber待发附件条数

onPatch(index, msg, busy)

流式输出时只有最后一条在变，宿主只推这一条。实现它，出字时就不用重绘整个列表 —— 这是「流式不卡」最有效的做法。不实现也能用（退回全量）。

onMentions({tools, plugins})

可被 @ 的工具与插件清单（{id, title, note}），用来画自己的 @ 选择器。

onSendResult(ok, errorText)

当前版本预留，宿主尚未调用；实现无副作用，但别依赖它做唯一反馈。

S.6 消息对象

{
  role: 'user' | 'assistant',
  content: string,        // Markdown 原文，宿主不做 HTML 渲染
  reasoning: string,      // 思考过程
  reasoningMs: number,    // 思考耗时
  pending: boolean,       // 该条仍在流式生成
  error: string | null,
  marks: [{ text, occurrence, color, kind }],
  quote: { text, color } | null,
  tools: [{
    name, summary,
    status: 'awaitingConfirm' | 'running' | 'success' | 'failed' | 'rejected',
    args: string,         // 参数原始 JSON 字符串
    output: string,
    error: boolean
  }]
}
content 是 Markdown 源文。不要直接 innerHTML = content —— 那等于把模型输出当 HTML 执行。要么自己解析，要么 textContent 原样显示。

标记颜色

color含义
yellow默认荧光笔
green / blue / pink其它荧光笔色
quote引用锚点（虚线），系统保留

S.7 推送节流与截断

规则值为什么
指纹比对条数 + 最后一条内容/思考/pending/error + busy没变就不推
按消息缓存只有变化的那条重新编码长会话不必整段重算
增量通道onPatch 约 60ms跟得上出字速度
全量间隔<16KB→120ms；16–48KB→180ms；>48KB→260ms载荷大时别排队堆积
reasoning 上限4000 字跨桥体积
tools args / output各 1200 字命令输出可能上百 KB

推论：收到的是近似连续而非逐字更新；也不要假设 args / output 完整（超长会标注「已截断」）。

S.8 本地图片与文件

做法说明
<img src="file:///…">页面从 file:// 加载，本地图片可直接显示
App.image(path)返回 data: URI；失败返回 ! 开头的原因
App.images(text)解析正文里的 Markdown 图片，返回 [{alt, src, remote, data}]
App.open(path)用系统查看器打开文件

可读目录：应用私有目录、外部私有目录（含附件）、相册与下载。单张图上限 6 MB，一条消息最多 24 张。

// 一定要在页面端缓存 data URI
const cache = new Map();
async function pictureFor(im) {
  if (im.remote) return im.src;
  if (cache.has(im.src)) return cache.get(im.src);
  const d = await window.App.image(im.src);
  if (d.startsWith('data:')) cache.set(im.src, d);
  return d;
}

设置值结果
javaScriptEnabledtrue页面可以跑脚本（这是功能定义）
allowFileAccesstrue页面能引用本地图片与文件
allowUniversalAccessFromFileURLstrue本地页面能请求 https（在线音频、CDN 图表）

S.10 性能硬要求

禁止 / 要求原因
❌ backdrop-filter: blur()Android WebView 上每帧重模糊整个可视区，滚动直接掉帧
❌ 每次推送 innerHTML = ''每秒数次 × 几十条 = 每秒重建数百节点，滚动位置也被重置
✅ 条数不变只更新最后一条消息只会追加或整条替换，这个判断安全
✅ 长列表用固定容器 + overflow-y:auto避免整页撑高导致布局抖动
✅ 大图懒加载 / 内联 SVG解码大图会卡主线程

S.12 排查

症状先查什么
一片白屏宿主会弹一条错误提示（加载失败 / JS 报错 / 注入失败），先看它
window.App.xxx is not a function该回调没实现。新版宿主会跳过，老包建议同步
消息不出现是否实现了 onMessages？名字大小写敏感
发送没反应handler 名必须正好是 send，参数是字符串
颜色不跟随深浅色是否在 onTheme 里写了 CSS 变量？宿主会重调，但不会 reload 页面
消息重复你做了追加，而宿主推的是全量
滚动卡检查 backdrop-filter、大阴影、是否每次全量重建

GUIDE操作指南（逐步）

这一章是"手把手"：每一项功能从哪进、点什么、看到什么、怎么改回来。 遇到不熟的地方，按编号一步步来即可。

G.1 第一次打开应用

  1. 打开应用 → 左上角圆形按钮打开侧边菜单
  2. 点「设置」→ 找到「模型设置」
  3. 点「新建档案」，依次填：显示名、Base URL、API Key、模型名
  4. 点「测试」—— 能收到一句回复就说明通了
  5. 返回聊天页，输入框上方会显示这个档案的显示名
填错时不要反复重发消息：先在设置里点「测试」，那一步失败会直接告诉你 是地址不对、密钥不对，还是模型名不存在。

G.2 发一条消息

  1. 在输入框里描述任务，可以只说目标，不用管步骤
  2. 需要附件时点左边的 ＋：选图 / 选文件，缩略图会挂在输入框上方
  3. 点右侧圆形按钮发送；生成中它会变成停止
  4. 想中途叫停：点停止，已生成的内容会保留

G.3 换模型

  1. 点输入框上方的模型胶囊（显示当前档案名）
  2. 在列表里选另一个档案 → 立即生效，历史继续沿用
  3. 同一次弹层里还能调思考深度（仅对支持推理的模型有意义）

也可以走：聊天右上角圆按钮 → 选择模型，两个入口等价。

G.4 标记与引用

  1. 长按消息里的文字 → 选中一段 → 选择颜色，即完成划重点
  2. 想取消：同样的位置再长按 → 选「取消标记」
  3. 想接着某句说：长按 → 「引用并回复」→ 引用条出现在输入框上方
  4. 发出去后，原文那里会留一道虚线锚点，回头能看出"这句话被接过"

G.5 建一个群聊

  1. 侧边菜单 → 「新对话」右侧的图标行 → 群聊入口
  2. 依次添加成员：给每个成员起名、写人设、选模型
  3. 设定发言方式：轮流 / 随机 / 手动点名
  4. 在输入框用 @ 点名某个成员，只有他回答
  5. 想插话：直接输入并发送；想打断：点停止

G.6 存一套做法（自定义工具）

  1. 设置 → 工具 → 右上角「新建工具」
  2. 填名字（如 合并PDF），进入详情页
  3. 编辑 tool.md：写清"什么时候用、怎么做、注意什么"
  4. 需要脚本就新建文件（如 merge.py），引用路径写相对名
  5. 回到聊天里说「用合并PDF处理这个目录」，模型会读那份说明

G.7 写一条规则

  1. 设置 → 自定义规则 → 新建
  2. 写一句可判定的话，例如「回答先给结论，再给理由」
  3. 保存后立刻生效，之后每一轮对话都受它约束
规则和"记忆"的区别：规则是硬性约束（永远照做），记忆是关于你的事实（会被引用）。 不要把所有偏好都写成规则 —— 太多规则会互相打架。

G.8 让它记事

  1. 直接说「记一下：下周要去上海出差三天」
  2. 它会存进笔记（或计划，看内容性质）
  3. 之后问「我下周有什么安排」，它会翻出来回答
  4. 想改：设置 → 管理记忆 / 笔记页，逐条编辑或删除

G.9 开一个常驻聊天（autopilot）

  1. 在输入框里提到 autopilot（手打或从 @ 面板选）—— 这条聊天立刻变成常驻
  2. 点右上角圆按钮 → 出现 Autopilot 文件
  3. 进去后点「新建」，填文件名（如 check.sh）与内容，保存
  4. 点那个文件名，把它设为入口脚本
  5. 选间隔：10s / 30s / 60s / 5m / 30m，或点「自定义」输入 45、5m、2h
  6. 打开上方「常驻运行」开关；想立刻验证就点脚本行的 ▶
  7. 侧边菜单的历史列表里，这条会话标题左边会出现循环箭头图标

G.10 写一个能用的常驻脚本

原则只有一条：没事发生就不要有输出。

#!/bin/sh
# 有情况才 echo，没情况直接 exit 0
value=$(curl -s "https://example.com/api/state" | jq -r '.value')
[ "$value" = "ok" ] && exit 0        # 正常 → 静默
echo "状态异常：$value"               # 异常 → 输出，模型会被叫醒
输出情况会发生什么
没有输出 / 只有空格继续下一轮，模型完全不被调用
和上一轮一样同上（这轮当作没变化）
和上一轮不同内容交给模型，结论回到这个会话；应用在后台时另发通知

G.11 做一个主题包

  1. 设置 → UI 设置 → 外观 → 「主题包（HTML 界面）」
  2. 点「新建主题包」：填名字、选主题色、写 HTML（会自动预填一份能跑的示例）
  3. 保存后点它 → 立刻切过去；想回原生界面点「应用默认界面」
  4. 也可以点「从剪贴板导入（HTML / JSON）」，把别处复制的内容直接变成主题包
  5. 编辑时按 ? 按钮可以看完整接口说明
最快的方式是让 AI 写：直接说「把聊天界面做成深色极简，带思考折叠」， 它会生成一个主题包。写坏了切回默认界面即可，数据不受影响。

G.12 加一把锁

  1. 设置 → 密码与安全
  2. 输入密码两次（至少 4 位）→ 保存
  3. 在「保护范围」里逐个打开需要保护的项目
  4. 想用指纹 / 面部：打开「用指纹 / 面部解锁」（设备没有锁屏凭据时此项不可用）
  5. 忘记密码或者在别的设备上恢复：只能重设（密码不存明文，无法读回）

G.13 导出与换机

  1. 设置 → 存储 → 「导出备份」，选一个保存位置
  2. 新设备上装好后：设置 → 存储 → 「导入备份」，选那份文件
  3. 主题包也可以在列表里单独导出成 JSON，便于分享给朋友

G.14 看它到底做了什么

  1. 消息下方「思考 3.2s」点开 → 看完整推理过程
  2. 「工具 · N」点开 → 每一次调用的名字、参数、输出、耗时
  3. 右上角圆按钮 → 工具调用 → 「性能」页 → 每一步花了多久、哪个最慢
  4. 命令正在跑时，会出现终端入口，可以看实时输出
